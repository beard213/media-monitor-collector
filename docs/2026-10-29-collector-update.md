# 采集端更新说明（2026-10-29）

本次更新将境外社媒采集端从“可单次触发的适配器集合”补齐为可持续运行、可恢复、可观测的采集服务。覆盖 YouTube、TikTok、Facebook、X、Instagram 五个平台。

## 本次已落地

### 1. 采集调度与任务恢复

- 新增采集任务 API：关键词、账号、首页流、直播任务均可异步提交、查询状态、读取日志和取消。
- 任务状态持久化。服务受控重启后，未完成的账号和直播任务会在有限次数内恢复，而不是直接丢失。
- 账号任务、关键词任务与直播任务分开限流：直播不占用短视频采集槽位；普通账号并发有上限，给浏览器、上传和 HLS 转推预留资源。
- 对重复提交做任务签名去重。调度心跳中的 `taskId`、提交时间等易变字段不再造成同一批账号被反复派发。
- 支持优先账号巡检配置：重点账号可高频检查最新内容，常规账号保留低频、增量的采集策略。

### 2. 关键词补量与平台保护

- 关键词任务支持每平台独立执行、关键词数据库兜底、发布时间过滤和运行进度回调。
- 单个关键词失败不会中断整轮；网络超时、平台拒绝、登录失效、磁盘空间不足等错误会以结构化状态返回。
- 平台任务锁、冷却和退避逻辑避免同一平台的失败任务持续占满采集槽位。
- 补量脚本支持 TikTok、X、Instagram 及关键词兜底队列；评论失败不会阻断视频、封面和发布时间的入库链路。
- X 搜索固定为视频结果入口，避免误落入仅展示实时动态的搜索筛选。

### 3. 浏览器登录态、媒体和评论

- 增加持久化 Chromium Profile、CDP 连接和浏览器守护脚本，浏览器型平台可复用登录态，而不是为每个任务新建浏览器。
- TikTok、Facebook、Instagram、X 的搜索和详情采集均支持浏览器路径；YouTube 保留 `yt-dlp`、Cookie 池与浏览器回退。
- 统一采集内容元数据、可播放媒体、缩略图、发布时间和评论；媒体/封面失败会保留可定位的错误，不伪报为成功。
- 评论结构支持作者 ID、昵称和主页 URL 回传，为后端按评论作者发现、去重和后续账号续采提供字段基础。
- Facebook checkpoint、Instagram 登录墙等场景会明确标记为登录态异常，交给冷却/人工登录处理，避免无效重试。

### 4. 直播稳定性

- 新增直播监测 API、会话持久化、心跳与停止控制。
- HLS 中继按直播场次管理片段，直播结束、源端中断和恢复过程有明确状态，而不是将短视频下载逻辑直接复用到直播。
- 直播恢复有并发上限，防止服务重启时大量历史任务同时启动 FFmpeg 导致宿主机资源被挤占。

### 5. 后端同步、清理与 Agent 对接

- 下游同步改为按内容处理回执；媒体、封面、评论和作者字段均进入统一批次。
- 成功同步后可清理本地临时视频、缩略图和转码中间文件；失败文件按保留期延迟清理，并在任务结束后触发垃圾回收，降低长期运行的磁盘和内存压力。
- 新增 Agent ingest 客户端：将标题、描述、ASR/OCR、关键帧、评论、媒体对象地址和关键词上下文发送给智能分析服务；调用具备超时、有限重试和失败回执。

## 运维注意事项

- 平台可用性依赖有效的浏览器 Profile/Cookie、出口网络和平台侧风控状态。`ACCESS_DENIED`、403、checkpoint 或登录页不是“已采集成功”，应进入冷却并恢复登录态后再试。
- 关键词采集的“候选数”“媒体下载数”“内容同步数”和“后端新插入数”是不同口径；运行报告应以后端新插入回执判断真实新增量。
- 不要提交 `.env`、浏览器 Profile、Cookie、运行日志、任务输出或私钥。仓库仅保留 `.env.example` 和可复现的部署/运行脚本。

## 建议验证顺序

1. 配置各平台 Profile/CDP 与后端同步凭据，启动浏览器守护和 API 服务。
2. 每个平台分别提交一条 `collectComments=true` 的小批量关键词任务，检查视频、封面、发布时间、评论作者字段和下游回执。
3. 验证平台锁/冷却在 403、登录失效和超时时能释放队列。
4. 再开启连续补量与重点账号巡检；直播任务应按独立资源上限逐步启用。
